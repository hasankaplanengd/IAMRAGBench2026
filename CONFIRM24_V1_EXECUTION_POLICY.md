# Confirm-24 v1 execution and rerun policy

## Purpose

This policy freezes the Confirm-24 execution rules before any Confirm-24 model
generation is run.

## Execution rule

Confirm-24 uses one temperature-zero generation per prompt. The generated output
is kept as the experimental observation.

## Permitted reruns

A config may be rerun only if the run is technically invalid, including:

- the generation command fails before completing all 24 pairs;
- the run directory is missing required files;
- `summary_overall.json` or `per_sample.csv` is missing;
- raw/repaired output files are missing;
- the provider call fails due to credentials, access, throttling, service outage,
  or another infrastructure problem.

## Non-permitted reruns

A config must not be rerun because:

- semantic candidate count is low;
- exact attack rate is low;
- a model is robust;
- output quality is disappointing;
- another run might produce a higher ASR.

Malformed JSON or non-policy text generated by the model is treated as a model
failure, not a rerun trigger, unless the malformed output is caused by a documented
runner or infrastructure bug.

## Reporting rule

All technically valid Confirm-24 generations are retained and reported. If a
technical rerun is required, the failed run, reason, and replacement run must be
recorded in the Confirm-24 execution manifest.

## Scope

This policy applies to:

- `data/confirm24_v1/rag_pairs_confirm24_v1_ordinary_run_eval.jsonl`
- `data/confirm24_v1/rag_pairs_confirm24_v1_authority_run_eval.jsonl`
- `configs/confirm24_v1_ordinary_*.yaml`
- `configs/confirm24_v1_authority_*.yaml`
- `scripts/score_confirm24_v1_run.py`
